# Power

React + Spring Boot + MySQL 기반 개인 프로젝트 배포용 구조입니다.

## 기능 명세

### 공통

- `React + Spring Boot + MySQL` 기반의 개인 일정/비용/후보 관리 서비스입니다.
- 로그인 후 좌측 메뉴에서 `체크리스트`, `인원관리`, `예산관리`, `웨딩홀`, `스드메`, `보금자리`, `설정` 화면으로 이동합니다.
- 모든 주요 데이터는 로그인 사용자의 `personalId` 기준으로 분리됩니다.
- 사용자는 DB의 `app_users` 테이블에 직접 추가하는 방식으로 관리합니다.
- 비밀번호는 SHA-256 해시값으로 저장합니다.
- 기본 계정은 `id: 160429`, `pw: 160429`, `nickname: zeroy`입니다.
- 좌측 메뉴는 접기/펼치기를 지원합니다.
- 모바일 크기에서는 상단 영역에 닉네임과 로그아웃 아이콘을 표시합니다.
- 다크모드를 지원하며, 사용자별 설정값을 DB에 저장합니다.
- 설정한 첫 화면 메뉴에 따라 로그인 또는 새로고침 후 진입 메뉴가 결정됩니다.

### 로그인

- 회원가입 화면은 제공하지 않습니다.
- DB에 등록된 `id`, `pw`, `personalId`, `nickname` 기준으로 로그인합니다.
- 로그인 성공 시 쿠키 기반으로 로그인 상태를 유지합니다.
- 쿠키에 유효한 로그인 정보가 있으면 설정된 첫 화면 메뉴로 이동합니다.
- 로그아웃 시 쿠키를 제거하고 로그인 화면으로 이동합니다.

### 체크리스트

- 결혼 준비 항목을 분류별로 관리합니다.
- 분류는 `결혼 몇개월 전`, `본식`, `본식 이후`처럼 체크리스트를 묶는 큰 단위입니다.
- 분류 관리 팝업에서 분류를 추가, 수정, 삭제할 수 있습니다.
- 체크리스트가 포함된 분류는 삭제할 수 없습니다.
- 분류별 색상을 선택할 수 있으며, 다크모드에서는 자동으로 밝기를 낮춰 표시합니다.
- 분류 로우를 클릭하면 해당 분류에 체크리스트 항목을 추가합니다.
- 항목 컬럼은 `카테고리`, `할일`, `담당`, `메모`, `완료여부`, `완료일`입니다.
- 항목을 저장하면 텍스트 형태로 표시합니다.
- 저장된 항목은 더블클릭하여 수정 모드로 전환할 수 있습니다.
- 수정 내용은 즉시 DB에 반영하지 않고, `저장` 버튼을 눌러 일괄 저장합니다.
- 신규/수정 건수가 있을 때 상단에 `신규 N건`, `수정 N건`으로 표시합니다.
- 삭제 체크박스로 다중 선택 후 삭제할 수 있습니다.
- 헤더 체크박스로 전체 선택/해제를 지원합니다.
- 로우선택 핸들을 드래그하여 항목 순서와 소속 분류를 변경할 수 있습니다.
- 드래그 중 이동 위치를 라인으로 표시합니다.
- 전체 항목 수, 완료 수, 완료 퍼센트를 진행률로 표시합니다.

### 인원관리

- 초대/참석 대상자를 대분류와 소분류 기준으로 관리합니다.
- 분류 관리 팝업에서 `대분류`, `소분류`, `소분류 퍼센티지`를 추가, 수정, 삭제할 수 있습니다.
- 이미 대상자가 사용 중인 분류는 삭제할 수 없으며, 검증 문구는 팝업 내부에 표시합니다.
- 대상자 컬럼은 `대분류`, `소분류`, `퍼센티지`, `성명`, `대상자와 관계`, `금액`, `청첩장`, `메모`, `대상자 수`, `적용 수`, `합계`입니다.
- 저장된 데이터는 텍스트 형태로 표시합니다.
- 저장된 셀은 더블클릭하여 수정할 수 있고, 수정은 `저장` 버튼을 눌러 일괄 반영합니다.
- 신규 로우는 분류 머지를 적용하지 않아 로우별로 대분류/소분류를 선택할 수 있습니다.
- 저장된 데이터는 같은 대분류/소분류 기준으로 셀을 머지하여 표시합니다.
- 대분류를 선택하면 해당 대분류의 소분류만 선택할 수 있습니다.
- 소분류를 선택하면 퍼센티지가 자동 적용되며, 퍼센티지는 대상자 로우에서 직접 수정하지 않습니다.
- 대상자 수는 같은 소분류에 포함된 저장 대상자 수로 계산합니다.
- 적용 수는 대상자 수에 퍼센티지를 적용하고 반올림하여 계산합니다.
- 필터는 `대분류`, `소분류`, `성명`을 지원합니다.
- 작은 화면에서는 필터가 기본 접힘 상태로 표시되며 펼칠 수 있습니다.
- 필터 기준으로 하단 합계를 표시합니다.
  - 전체 대상자 수
  - 전체 금액
  - 적용 대상자 수
  - 금액 합계
- 금액은 퍼센티지 계산 없이 단순 합산합니다.
- 삭제 체크박스로 다중 선택 후 삭제할 수 있습니다.
- 헤더 체크박스로 전체 선택/해제를 지원합니다.

### 예산관리

- 결혼 예산과 실제 지출을 대분류 기준으로 관리합니다.
- `간단하게 보기` 옵션을 지원하며, 선택값은 로컬에 유지됩니다.
- 간단하게 보기에서는 예산/잔여 관련 컬럼을 숨기고 지출 중심으로 표시합니다.
- 상단 요약 박스에서 주요 금액을 표시합니다.
  - 나의 예산: 가용금액 / 전체금액
  - 예상 지출
  - 가용 기준 여유
  - 전체 기준 여유
- `나의 예산` 박스를 클릭하면 나의 예산 관리 팝업을 엽니다.
- 나의 예산 관리에서는 `소유자`, `구분`, `자산명`, `금액`, `비고`를 관리합니다.
- 예산 구분은 `가용`, `비가용`을 지원합니다.
- 대분류 관리 팝업에서 예산 대분류와 배정금액을 관리합니다.
- 대분류 관리 팝업 안에서 나의 예산 가용/전체 금액을 함께 확인할 수 있습니다.
- 대분류별 요약을 표시합니다.
  - 대분류
  - 배정금액
  - 지출합계
  - 잔여금액
  - 상태
- 예산 상세내역 컬럼은 `대분류`, `세부항목`, `지출(원)`, `비고`입니다.
- 지출 금액이 비어 있으면 내부적으로 `0`으로 저장합니다.
- 신규/수정 건수가 있을 때 상단에 `신규 N건`, `수정 N건`으로 표시합니다.
- 삭제 체크박스로 다중 선택 후 삭제할 수 있습니다.
- 저장된 데이터는 텍스트 형태로 표시하고, 더블클릭 시 수정할 수 있습니다.
- 수정 내용은 `저장` 버튼을 눌러 일괄 반영합니다.
- 화면 폭이 좁아지면 요약/상세 테이블에 횡스크롤을 제공합니다.

### 설정

- 사용자별 화면 옵션을 관리합니다.
- 설정값은 `user_settings` 테이블에 `personalId`, `optionKey`, `optionValue` 구조로 저장합니다.
- 다크모드를 켜고 끌 수 있습니다.
- 다크모드 선택값은 다음 접속 시에도 유지됩니다.

- 첫 화면 메뉴는 로그인 또는 새로고침 후 자동 이동할 메뉴를 의미합니다.
- 선택 가능한 첫 화면 메뉴는 `체크리스트`, `인원관리`, `예산관리`, `웨딩홀`, `스드메`, `보금자리`, `설정`입니다.

```text
compose.prod.yml  Docker Compose EC2 배포 실행
```

## Docker Compose - 로컬

로컬에서는 DBeaver 접속과 개발 확인을 위해 MySQL, Backend, Frontend 포트를 모두 호스트에 공개합니다.

```bash
docker compose up
```

백그라운드 실행:

```bash
docker compose up -d
```

종료:

```bash
docker compose down
```

DB 볼륨까지 삭제:

```bash
docker compose down -v
```

접속 주소:

```text
Frontend  http://localhost:9090
Backend   http://localhost:9096/api/health
MySQL     localhost:3308
```

Compose의 MySQL 접속 정보:

```text
host      localhost
port      3308
database  personal_project
username  appuser
password  apppassword
root      rootpassword
```

## Docker Compose - EC2 배포

EC2에서는 `compose.prod.yml`을 사용합니다.

```bash
docker compose -f compose.prod.yml up -d --build
```

배포용 compose는 외부 공개를 최소화합니다.

```text
Frontend  EC2_PUBLIC_IP:9090 공개
MySQL     EC2_PUBLIC_IP:3308 공개
Backend   외부 미공개, Docker 내부에서만 접근
```

DBeaver로 EC2 MySQL에 접속하려면 AWS 보안그룹에서 `3308`을 열어야 합니다. 단, `0.0.0.0/0`이 아니라 접속할 PC의 공인 IP만 허용하세요.

```text
Type        Port  Source
SSH         22    내 IP
Custom TCP  9090  내 IP + 함께 사용할 사람 IP
Custom TCP  3308  내 IP
```

EC2에서 환경값을 바꾸고 싶으면 `.env`를 만들어 사용합니다.

```bash
MYSQL_DATABASE=personal_project
MYSQL_USER=appuser
MYSQL_PASSWORD=강한비밀번호
MYSQL_ROOT_PASSWORD=강한루트비밀번호
MYSQL_PUBLIC_PORT=3308
FRONTEND_PUBLIC_PORT=9090
CORS_ALLOWED_ORIGINS=http://EC2_PUBLIC_IP:9090
```

DBeaver 접속 정보:

```text
host      EC2_PUBLIC_IP
port      3308
database  personal_project
username  appuser
password  .env의 MYSQL_PASSWORD
```

DB 데이터는 Docker volume `mysql-data`에 저장됩니다. 운영 데이터가 들어간 뒤에는 아래 명령은 사용하지 마세요.

```bash
docker compose -f compose.prod.yml down -v
```

## Backend

```bash
cd backend
./gradlew bootRun --args='--spring.profiles.active=local'
```

로컬 백엔드는 기본적으로 `9096` 포트에서 실행됩니다.

```text
http://localhost:9096/api/health
```

기본 환경변수:

```bash
DB_URL='jdbc:mysql://localhost:3306/personal_project?serverTimezone=Asia/Seoul&characterEncoding=UTF-8'
DB_USERNAME=appuser
DB_PASSWORD=change-me
```

API:

```text
GET  /api/health
GET  /api/posts
POST /api/posts
```

## Frontend

```bash
cd frontend
npm install
npm run dev
```

로컬 프론트는 고정 포트 `9090`에서 실행됩니다.

```text
http://localhost:9090
```

프로덕션 빌드:

```bash
npm run build
```

EC2에서 Nginx가 같은 도메인의 `/api`를 백엔드로 프록시하므로, 운영 빌드에서는 `VITE_API_BASE_URL`을 비워둡니다.
로컬 개발 서버에서는 Vite proxy가 `/api` 요청을 `http://localhost:9096`으로 전달합니다.
